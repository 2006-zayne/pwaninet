Mobile Fullscreen Reel Player — Full Width, No Crop, Blur Fill

Your call: keep the whole width of the video (nothing cropped on the left/right) and still fill the screen top-to-bottom.
The only way to do both is to let the video keep its own height and fill the leftover space with a blurred version of the video — the Instagram / TikTok / Facebook Reels look. Two fills are previewed below: A = blurred poster frame (cheap, static), B = live blurred copy of the video (moves with the content). Mockup replicates the real DOM + the real CSS rules from static/css/postcard.css.

Same rule: fill the width, keep the video's own height, and the rest of the screen gets the blurred fill. For a 16:9 source the band is tall (≈315px on an iPhone 15 Pro) so the blur fill matters even more here — option B keeps the fill alive with the actual footage.

What gets changed once you approve (implementation plan)

1 · CSS — make the ambient fill look intentional

/* static/css/postcard.css — .reel-ambient-img today is very dark */
/* filter: blur(36px) brightness(0.4) saturate(1.2); transform: scale(1.15);  */
.reel-ambient-backdrop {
  position: absolute;
  inset: 0;                    /* was -24px: fill the whole stage, not just the letterbox */
  overflow: hidden;
  z-index: 0;
}
.reel-ambient-img {
  width: 100%; height: 100%; object-fit: cover;
  filter: blur(46px) brightness(0.62) saturate(1.45);
  transform: scale(1.28);
}

The video itself stays object-fit: contain — nothing about the crop changes, only how the leftover space looks.

2 · Option B (live blurred copy) — one extra element + sync

/* static/js/video-manager.js → buildSnapItemFromReelCard(): inside .reel-ambient-backdrop */
<video class="reel-ambient-video"
       muted loop playsinline preload="none"
       data-video-url="${videoSrc}"></video>

/* keep it locked to the main video */
main.addEventListener('timeupdate', () => {
    if (Math.abs(ambient.currentTime - main.currentTime) > 0.25) {
        ambient.currentTime = main.currentTime;   // re-sync after seeks / stalls
    }
});
main.addEventListener('seeked',  () => ambient.currentTime = main.currentTime);
main.addEventListener('play',    () => ambient.play().catch(() => {}));
main.addEventListener('pause',   () => ambient.pause());

3 · Cost / edge cases

  • Option B costs a second decoder + a second stream. For HLS reels that means double segment traffic, so B is recommended for direct MP4 reels and the poster fill (A) for HLS.
  • Option A costs one extra JPEG (the poster) — most posts already have one (post.video_poster); posts without a poster fall back to a plain dark fill.
  • The ambient layer must pause when the reel scrolls out of view (it already pauses for the main video in the snap observer).
  • Overlays are unaffected: caption block, engagement rail and scrubber already sit on top with env(safe-area-inset-*) padding.
  • Desktop player, feed cards and the reel rail are untouched by this change.
Decide before I build: A (blurred poster — one cached JPEG, static, works for every source incl. HLS) or B (live blurred copy — exact Instagram look, but a 2nd decoder and a 2nd stream on every reel)?
Recommended: A everywhere by default, and B only for direct-MP4 reels if you want the fill to move with the footage. Optional extra: a per-post toggle so an author can force “fit” (plain letterbox) instead of the blur fill.
